# 金融评测与打分规则

本文件记录金融版本当前实际执行的规则。网页说明见 [`public/methodology.html`](../public/methodology.html)，实现以 `src/a2a.js`、`src/scoring.js`、`src/prompts.js` 和 `src/pipeline.js` 为准。

## 0. A2A 准入

准入只决定能否创建评测，不计分。Agent Card 必须是 JSON 对象，包含非空 `name`、`description`，至少声明一个具备 `id / name / description` 的 skill，并提供 A2A 1.0 `supportedInterfaces` 或兼容 0.3 的顶层 `url`。

Card URL / 服务发现还检查 HTTP(S)、私网 URL 策略、1 MB 响应上限与禁止重定向。失败返回 HTTP 400，不进入后续阶段。

## 1. 投研 Agent 必要性

程序拼接 Card 描述、skills 的名称/描述/tags/examples 和全部测试 prompt，扫描 8 组金融复杂信号：

| 组 | 信号 |
|---|---|
| G1 | 行情、财务、指数、行业、交易日历、Data Skill、API |
| G2 | 截止日、样本期、滚动窗口、交易日、频率、复权、point-in-time |
| G3 | 因子、IC、Rank IC、分组回测、中性化、标准化 |
| G4 | 回测、基准、手续费、滑点、换手、撮合、停牌、涨跌停 |
| G5 | 组合、持仓、风险暴露、归因、再平衡、回撤、压力测试 |
| G6 | 多步、workflow、编排、多智能体、Agent 协同 |
| G7 | 证据、来源、图表、研究报告、可解释、假设、局限 |
| G8 | 合规、权限、授权数据、投资建议、人工确认、审计、可复现 |

简单问答组 `S` 匹配查股价、查行情、公司简介、新闻摘要、整理文件、重命名、摘要、翻译、改写等单轮任务。变量：

- `C`：命中的复杂信号组数量，0–8；
- `S`：是否命中简单问答组，0 或 1；
- `K`：skill 数量；
- `N`：测试用例数量；
- `U`：是否存在测试用例；
- `B`：`streaming +5`、`pushNotifications +6`、非空 `extensions +4`。

五维公式：

```text
研究链路       = clamp(18 + 10C - 5S)
数据依赖       = clamp(12 + 9C + 3K)
时点与状态     = clamp(10 + 8C + B)
决策不确定性   = clamp(22 + 8U + 5C)
工作流复用     = clamp(26 + 7K + 4N + 4C)
必要性总分     = round(五维算术平均)
```

`clamp(x) = min(100, max(0, x))`。阈值：0–35 为“模型直出更划算”，36–59 为“Agent 价值存疑”，60–100 为“值得 Agent 化”。必要性低于 36 时最终评级强制为“拉”。

## 2. 四方 Agent Card 设计审稿

新建 V1 使用 `v1-card-review/v2`。OpenAI、Anthropic、豆包和 DeepSeek 四席只看完整公开 Agent Card，只评审 Card 的设计是否合理；它们不能把 Card 中的自述当成工具、数据或研究结果已被验证的证据，也不评价尚未执行的同题输出。每席返回简体中文评语和首要风险。

五个等权维度均为 0–100，正式总分由服务端取五项平均，而不是采信模型自报总分：

1. `positioningClarity`：定位、目标问题、用户与适用边界是否清晰；
2. `skillDesign`：Skills 的拆分、命名、覆盖、输入预期是否合理；
3. `protocolCoherence`：A2A 协议、接口、能力与输入输出模式是否自洽；
4. `ioExampleQuality`：examples、tags 与输入输出示例是否足以调用和理解；
5. `boundaryRiskDisclosure`：数据时点、失败条件、合规、非投资建议与不可用状态是否明确。

成功席位按维度取算术平均；失败席保留错误但不阻断后续对打。投研 Agent 必要性仍是独立的场景信息，不进入 Card 设计分。

## 3. Description + Panda 公开研究基线

Claude Code、Cursor Agent 与 Doubao Agent 只收到顶层 `description` 原文，不能看到 name、skills、examples、tags、capabilities、Agent 接口、源码或提交 Agent 的输出。启用 Panda Data 时，三者还会收到相同的比赛 `接口文档.md` 白名单摘录；这属于主办方统一数据底座，不包含提交 Agent 的私有能力或任何凭据。

生成的金融 Skill 必须声明 `panda_data` 工具并记录数据来源、口径、截止时点、样本区间，防范未来数据泄漏，报告基准、交易成本、风险与局限，并声明不构成投资建议。每局执行前，Runtime 先生成 1–3 项白名单查询计划；平台校验后通过受限 Python bridge 执行，再把不含凭据的真实结果交给 Runtime。越权方法或畸形参数失败关闭。构建或执行失败时该 Runtime 的该局实战分为 0，其他选手继续执行。

## 4. 同题研究实战分

新建 V1 评测使用 `v1-model-arena/v2`；历史 `v1-model-arena/v1` 是旧的四维 Arena 规则，二者按记录中持久化的版本解释。不会后台迁移或静默重算历史 V1 记录。用户可选择：

- `single`：由所选的一位评审模型为同一 CASE 内的全部成功输出匿名评分；可选 OpenAI、Anthropic、豆包或 DeepSeek，缺省配置与进入单模型模式时均默认 DeepSeek。
- `panel`：固定使用 OpenAI、Anthropic、豆包和 DeepSeek 四席匿名盲评；至少两席成功才形成该 CASE 的正式分数。

每个 CASE 会先收齐提交 Agent 与全部 Runtime 的输出，再移除候选名称、Runtime ID、顺序、耗时和平台能力分，为每席生成独立的不透明候选 ID。评审只比较共享任务下的可见输出，不能浏览或调用工具。服务端严格校验每席返回值，`rationale` 与 `uncertainties` 必须包含简体中文，否则该席失败；总分按固定权重重算，模型自报的总分不参与最终计算：

```text
单局总分 = 0.20 × 场景价值 + 0.60 × 专业度 + 0.20 × Agent 能力

场景价值 = 0.50 × 问题复杂度 + 0.50 × Agent 适用性

专业度 = 0.30 × 任务完成
       + 0.25 × 方法专业性
       + 0.20 × 证据与数据质量
       + 0.15 × 风险与不确定性
       + 0.10 × 产物可用性
```

场景由每席对用例评一次，因而同一 CASE 的所有成功候选共享该场景分；专业度由每席对匿名可见输出评估。单模型模式采用该席经服务端重算的分数；四模型模式对每个子维度取成功席位中位数，再重算维度与总分。每个选手的最终实战分是全部正式评分 CASE 的算术平均，保留 1 位小数。

Agent 能力完全来自服务端本次执行记录：成功且有可见最终输出为 100 分，否则为 0 分；耗时 `durationMs ≤ 60,000` 为 100 分、`durationMs ≥ 600,000` 为 0 分，中间按 `100 × (600,000 - durationMs) / 540,000` 线性折算。执行失败总分硬置 0；成功候选的能力分为 `0.70 × 执行成功分 + 0.30 × 耗时分`。

耗时是候选调用开始至输出或失败结束的端到端墙钟统计，包含网络传输、A2A 协议轮询、Runtime 进程启动和模型处理。平台固定声明：**不观测 Agent 内部工具调用**；输出里的“已调用工具”等文字只可作为输出证据审查，不能变成能力分事实。

- 候选执行失败时固定为 `0`，标记 `execution-failed`，且不会发送给评分模型。
- 成功执行但单模型评分失败，或四模型不足两席成功时，候选不生成数字分并显示 `—`；CASE 保存席位错误，不生成最终评级。
- 模型评分失败不回退到关键词规则分、模拟分或历史分。一个 CASE 的全部候选均执行失败时无需调用模型，所有候选均为 `0`。
- “重跑这一局”会重新匿名评分该 CASE 的全部成功输出，并原子替换完整 CASE 评分快照，不会只为被重跑的候选补分。

真实模式开启 `PANDA_DATA_AUTO_VERIFY` 后，平台仍会在同局开始前锁定 PandaAI 参考快照，并将输出事实验真结果作为独立审计信息保存。`dataVerification` 不会进入发送给 V1 评审模型的候选包或 Prompt，V1 评分器也不读取它来计算专业度或总分；它不会绕过模型竞技评分或充当评分失败兜底。

用户显式重跑某个 CASE 才以该记录冻结的评分配置替换该 CASE 完整快照；这不是后台批量迁移。

## 5. 最终分档

设 `A` 为提交 Agent 均分，`C` 为 Claude Code 均分，`D` 为豆包均分，`N` 为必要性分，按顺序命中第一条：

1. `N < 36`：拉；
2. `A - C >= 3`：夯；
3. `A - C >= 0`：人上人；
4. `A - D < 0`：拉；
5. 其他：NPC。

## 6. 模式、重试与数据边界

- `demo`：完整走通流程，但模型、Runtime 或提交 Agent 输出可能是确定性模拟；
- `live`：真实调用对应适配器；
- `mixed`：部分真实、部分模拟或失败；
- `failed`：该步骤执行失败。

V1 `live` 创建会在任何 Agent 或 Runtime 启动前检查所需评审席的受支持类型、`baseUrl`、`model`、`apiKeyEnv` 及其引用的本地密钥是否存在。该检查不发送网络请求；网关连通性、远端鉴权与模型可用性仍由实际调用判定。

重试会替换旧结果并重算专业度、实战均分与最终评级，不取历史最高分。V1 任一同题候选重跑后会重评完整 CASE；根 seed 为 reviewer、Runtime、用例和评分席位派生稳定子 seed。

启用 Panda Data 的 Runtime 分成三个相互隔离阶段：以 description 和比赛 `接口文档.md` 白名单摘录生成 Skill；以 Skill、用户 Prompt 和白名单生成 1–3 项查询计划；平台用受限 Python bridge 真正执行允许的方法后，再以 Skill、Prompt 和结果证据生成最终输出。模型不会获得 Panda 用户名、密码、Token 或 bridge 环境变量。

结果按完整 JSON 行进行 UTF-8 字节预算：每项查询最多 **240,000 bytes**，同一最终调用的全部 Panda 结果最多 **600,000 bytes**。裁剪记录 `originalRows`、`keptRows`、`droppedRows` 与 `truncated`，并要求 Runtime 披露数据范围限制；不会截断半个对象。每次 Runtime 模型调用还在网络请求前检查完整输入：`MODEL_CONTEXT_MAX_BYTES=1500000`、`MODEL_CONTEXT_WARN_RATIO=0.8`。必保系统指令、输出契约和白名单不被静默裁剪；仍超限时以 `MODEL_CONTEXT_BUDGET_EXCEEDED` 失败，并持久化上下文用量审计。

公开首页仅提供 V1 `live` intake：不显示 V2 版本选择或 demo 入口，且创建请求固定为 `mode: "live"`。这只影响公开入口；V2、demo 的服务端 API、历史记录和直接结果页仍保留其原始类型，不能伪装成 V1 live。

完成的 `schemaVersion: 1` V1 记录可下载完整中文 PDF：`GET /api/evaluations/:id/report.pdf`。成功响应为 `application/pdf`、附件下载和 `Cache-Control: no-store`；不存在记录为 404，V2 或未完成记录为 409。报告即时生成，包含 Card、四方 Card 审稿、共享场景、逐候选专业度/能力/耗时、逐席中文评语、完整原始输出、Runtime/Panda/上下文审计；不包含凭据、环境变量、私有 V2 evidence 或模型思维过程。

金融结果只有在真实数据与投研 Skills 成功调用、数据版本和时点可审计、回测配置可复现时，才可以解释为一次真实技术实验；无论何种模式，系统输出都不构成投资建议。

## 7. 受治理的黑盒 V2 绝对分

本节描述 `schemaVersion: 2` 的 `a2a-black-box-v1` 规则。它与上文的历史
description-only MVP 分数并存；V2 不会静默重算 `schemaVersion: 1` 记录。

参赛者提交 A2A Agent Card 与 **Agent 使用示例**。平台执行原始、等价、边界和
多轮测试，并先完成四模型逐叶评审。仅被标记为分歧的叶子才由第五模型处理。模型席
锁定后，两名不同人工评委进行人工不盲审：他们可见脱敏提交、可见证据、客观指标与
模型意见，但在绝对分锁定前看不到 Replica 的 Runtime、输出、得分或优势。

每个叶子的两份人工分相差 **大于 15 分** 时，必须由第三名、且不同于两位主审的
仲裁评委评分；二人或三人的中位数才是人工叶分。人工评委的客户端不能提交权重、
总分或适用性，这些均由服务器从 rubric 和执行记录计算。

### 固定叶权重与席位

| 维度 | 叶与权重 | 席位公式 |
|---|---|---|
| 场景价值 | Agent 必要性 30、研究决策价值 30、效用复用 25、产品新意 15 | `0.4 × 模型席 + 0.6 × 人工席` |
| 专业性 | 任务完成 25、方法假设 25、证据推理 25、风险不确定性 15、产物可用性 10 | `0.4 × 模型席 + 0.6 × 人工席` |
| Agent 能力 | 测试成功 30、鲁棒性 20、上下文连续性 15、A2A 合规 15、效率 10、主张/错误处理 10 | `0.5 × 客观席 + 0.2 × 模型席 + 0.3 × 人工席` |

每个席位先按适用叶权重重分配后取加权均值。绝对总分是三个维度分的等权平均。
Agent 能力的客观覆盖率是可计算客观指标的覆盖比例；低于 `0.70` 时结果明确标为
“暂定”，而不是以缺失指标填充高分。

### 置信度与证据

每个 rubric 检查项聚合模型、人审和客观记录引用的证据 ID，取该检查项的最高证据
等级：A=`1`、B=`0.8`、C=`0.35`、D=`0.1`，无证据为 `0`。设：

```text
E  = 所有检查项最高证据等级的平均
Am = 1 - min(1, 模型分 IQR / 30)
Ah = 1 - min(1, 人工分极差 / 30)
A  = 0.6 × Am + 0.4 × Ah
R  = 模型置信度中位数
C叶 = 0.5 × E + 0.3 × A + 0.2 × R
```

维度置信度是适用叶的固定权重平均；总置信度是三个维度置信度的几何平均。缺少证据
的检查项会保留在 `evidenceGaps`，不会被自由文本理由替代。

绝对分锁定前必须已有四模型席、需要时的第五模型结论、两位完整主审以及所有人工
仲裁。锁定会写入不可变结果哈希；之后不能原位修改。

## 8. 复刻对照、Δc 与评级

绝对分锁定后才释放此前密封的 Replica Arena。匿名评分单元中，提交 Agent 与每个
有效 Replica 的分数形成同一评分立方体。每位匿名评审只对候选输出打四维分；服务端按固定权重重算总分，模型不得自报加权结果：

```text
arenaTotal = 0.40 × 任务约束 + 0.30 × 专业质量 + 0.20 × 证据风险 + 0.10 × 产物可用性
```

平台取提交 Agent 中位数，取各有效 Replica 中位数的最大者为最佳基线：

```text
Δ = submittedMedian - bestReplicaMedian
Δc = 对评分单元固定 seed bootstrap 10,000 次的 95% 区间下界
```

每次重采样都会重新选择最佳 Replica，因此 `Δc` 是保守复刻优势。区间跨过当前评级
阈值时，结果标为“差异未稳定”。没有有效 Replica 时保留绝对分，评级为“待复刻”。
Replica 分数从不进入绝对分。

| 评级 | 门槛 |
|---|---|
| 夯 | 总分 ≥ 80、场景价值 ≥ 60、客观覆盖率 ≥ 0.70、`Δc ≥ 5` |
| 人上人 | 总分 ≥ 70、场景价值 ≥ 50、`Δc ≥ -2` |
| NPC | 总分 ≥ 55、场景价值 ≥ 36、`Δc ≥ -10` |
| 拉 | 其他情况 |

未通过参评资格时不计算上述比较，显示“未通过参评资格”。
