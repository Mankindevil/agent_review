# A2A 金融 Agent 招募科普指南

## 一、你的金融 Agent，可能只差一个标准接口

如果你手上已经有一个能跑起来、能正常回答问题的金融 Agent——无论是行情速览、财务问答、因子研究还是交易策略助手——距离参加这场黑客松，很可能不是要重写一遍核心逻辑，而是补上一层对外的标准接口。这场赛事统一采用 A2A（Agent-to-Agent）协议完成对接与评审，只要你的 Agent 能对外暴露一份 Agent Card 并支持标准消息调用，就具备了报名的基础条件。

## 二、A2A 能做什么：发现、消息、任务状态与结果交付

A2A 协议定义了四类基础能力。发现：评审方通过读取 Agent Card 了解你的 Agent 叫什么、能做什么、有哪些 Skill、如何鉴权，不需要额外沟通文档。消息：评审方按标准格式发送一条消息（包含文本或结构化 Part），你的 Agent 处理后返回响应。任务状态：对于需要一定处理时间的请求，A2A 允许把执行过程建模为任务，评审方可以查询任务当前所处的状态。结果交付：最终结果以 Artifact 或消息 Part 的形式规范返回，方便评审方统一解析，而不必逐个适配不同团队自定义的返回格式。

## 三、A2A 是外部互操作边界，不规定你内部怎么做

需要强调的是，A2A 只约束你和评审方之间的“外层协议”，不干涉你的内部实现。你用什么大模型、写什么提示词、搭什么框架、接哪些工具链，都完全由你决定，无需公开这些内部细节，A2A 也不会去验证你内部具体调用了哪些工具。是否采用 Multi-Agent 架构同样不是强制项——单一 Agent 只要能稳定完成任务，同样符合参赛条件。换句话说，A2A 是一份对外接口协议，你的“黑盒”内部保持你原有的技术选择即可。

## 四、为什么统一走 A2A 评审

赛事选择统一走 A2A，核心原因是需要在同一套规则下完成公平打分。评审组要能对所有参赛作品做黑盒调用：不去看代码、不依赖选手自述，只看接口给出的真实响应。这样才能实现跨技术栈的公平对比——用不同语言、不同框架搭建的 Agent 都能被同一套调用逻辑评估。A2A 也支持可重复调用，评审组可以在不同轮次用相同或相近的任务重新验证结果；同时便于证据留存，关键结论可以在赛后复核，而不只依赖一次性演示。

## 五、现有能力 → 轻量适配，不是从零重建

已经有 Agent 在跑的团队，通常只需要在外层补上一份 Agent Card、一个标准消息入口，并把最终结果整理成规范返回格式即可完成对接，具体接入工作量因团队现状而异，我们不承诺固定的接入时长。同时，A2A 协议里较复杂的能力——比如流式输出、推送通知或多阶段任务生命周期管理——并不是所有参赛作品的强制要求，你可以先用最基础的同步消息调用跑通，再按需扩展。

## 六、评审关注的六个维度与一票否决边界

人工终审围绕六个维度展开：A2A 接入与稳定性，看 Agent Card 是否可发现、接口是否可稳定调用、鉴权是否清晰、出错后能否恢复；金融数据纪律，看数据是否有授权来源、口径是否清楚、是否遵守 point-in-time 与历史成分规则；研究方法与创新，看问题是否有价值、方法是否合理、因子或策略流程是否完整；回测与风险可信度，看基准选取、成交时点、交易成本与滑点处理、样本外表现与回撤暴露；解释性与可复现性，看假设、证据链、参数与样本期是否可复算，失败结果是否被诚实呈现而非编造；演示与提交完整度，看材料是否齐备、示例任务是否充分、文档与截图是否清楚。与此同时存在一票否决边界：出现恶意行为、数据窃取或绕过权限、使用未授权数据；伪造行情、财务数据、回测结果或第三方来源；宣称保证收益、直接荐股或代客理财、缺少必要风险提示；Agent Card 长期不可访问或服务无法调用且评审窗口内未恢复；作品无法以 A2A Remote Agent 形式运行——以上任一情形都会直接导致作品被否决，不进入正常打分。

## 七、最低投递材料与适合的方向

最低投递材料包括：一份可被外部访问的 Agent Card；一个可被稳定调用的服务端点；必要的鉴权方式说明；以及至少 3 个示例任务，需覆盖正常任务、信息不足和风险或失败边界这三类场景，用来展示你的 Agent 在标准输入、模糊输入和极端输入下的真实表现。适合投递的方向十分宽泛：金融研究、行情分析、因子挖掘、交易策略、风险控制、组合管理、事件研究等，只要能以 A2A Remote Agent 的形式稳定运行，都在欢迎范围内。

## 八、现在就可以报名

如果你的金融 Agent 已经能正常工作，不要因为“还没做好复杂功能”而犹豫——先把最基础的 A2A 接口跑通，带着 Agent Card 和 3 个示例任务报名，剩下的评审细节交给统一流程处理。作品通过 GitHub 仓库链接或发送至 `code@pandaai.online` 提交，欢迎已有可用 Agent 的团队尽快行动。
