# V1 提交 Agent 两小时超时设计

日期：2026-08-02

## 目标

将 V1 同 Prompt 对打中“提交 Agent”的 A2A 总截止时间从 90 秒提高到 2 小时。Claude Code、Cursor、豆包、Panda Data 与四模型评分维持现有超时，避免一次异常评测占用整个流水线数小时。

本调整只控制本平台最多等待多久。若对端 Agent、PandaOS 或其网关在 2 小时内主动返回 HTTP 502、其他非成功状态或协议错误，平台立即记录失败，不继续等待，也不自动重放已经建立连接的 POST 请求。

## 配置与边界

- 新增环境变量 `V1_SUBMITTED_AGENT_TIMEOUT_MS`。
- 默认值为 `7200000` 毫秒（2 小时）。
- 仅 V1 提交 Agent 的下列执行路径使用该值：
  - 普通单 Prompt A2A 调用；
  - Agent Example 与其真实多轮上下文调用；
  - “重跑这一局”中的提交 Agent 重跑；
  - 依赖相同提交 Agent 调用入口的定向复核。
- 不修改 A2A Agent Card 解析的 30 秒截止时间。
- 不修改 Claude Code、Cursor、豆包及模型评分的 180 秒截止时间。
- 不修改 Panda Data 单次查询的 60 秒截止时间。
- 不修改隐藏的 V2/黑盒执行策略。

配置解析只接受正整数，并设置 2 小时为默认值。为避免错误配置造成无限等待，最大值同样限制为 2 小时；超过最大值时收敛到 2 小时，非法或缺失值回退到 2 小时。

## 执行语义

Pipeline 在创建时解析一次提交 Agent 超时配置，并在所有 V1 提交 Agent 调用中复用。A2A executor 继续使用一个从开始时间计算的绝对 deadline；Agent 消息发送、任务轮询、快照读取和瞬时连接重试只能消费剩余时间，不能为每次重试重新获得两小时。

HTTP 502 等已经收到的非成功响应不属于瞬时建连失败。平台不自动重试此类响应，以免对同一个 Agent 重复创建任务或产生重复工具副作用。

## 反向代理

新建评测接口仍立即返回 202，后台流水线不需要让创建请求保持两小时。同步执行提交 Agent 重跑的 V1 API 路由需要单独设置略高于应用截止时间的 Nginx 上游读取/发送时限，采用 2 小时 5 分钟，确保应用先产生结构化超时结果，而不是由 Nginx 提前返回 504。

SSE 事件流和 PDF 下载维持各自既有策略。前端不新增计时器，用户仍可通过“停止本次评测”中止当前请求。

## 可观测性与界面

执行日志和最终报告继续记录端到端 wall-clock 耗时，包含网络与协议开销。失败信息应能区分：

- 本平台 2 小时总截止；
- 对端主动 HTTP 502；
- 用户取消；
- A2A 协议失败。

界面不把对端主动 502 描述为“平台超时”。配置文档明确显示提交 Agent 的默认上限为 2 小时。

## 测试与验收

测试必须先证明旧实现仍向提交 Agent 传入 90 秒，再实现以下行为：

1. 普通 V1 Prompt 调用收到 `7200000` 毫秒总截止时间。
2. Agent Example 调用收到同一截止时间。
3. 提交 Agent 重跑复用相同配置。
4. 非提交候选与模型评分仍为 180 秒，Panda Data 仍为 60 秒。
5. A2A 内部重试共享一个 deadline 的既有测试继续通过。
6. Nginx 的同步 V1 重跑路由时限高于 2 小时应用截止时间。
7. `.env.example`、README 配置表和部署环境模板包含新变量。
8. 生产部署后健康接口正常，并通过只读配置检查确认运行进程获得 `V1_SUBMITTED_AGENT_TIMEOUT_MS=7200000`。

不使用真实长达两小时的等待作为测试；自动化测试通过注入配置和捕获传参验证行为。
