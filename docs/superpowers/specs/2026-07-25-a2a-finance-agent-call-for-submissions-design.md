# A2A 金融 Agent 征集文案设计

## 目标

面向 PandaAI 赛道选手生成两篇可直接发布的中文 Markdown 文案，用通俗语言说明 A2A 协议、平台采用 A2A 的评审原因，并邀请所有金融相关 Agent 队伍投递。

两篇文案分别承担不同任务：

- 短公告用于选手群、群公告和活动页面快速触达；
- 招募型科普稿用于完整解释 A2A、评审方式和接入成本。

## 篇幅与语气

- 短公告控制在约 600–800 字；招募型科普稿控制在约 1500–2000 字。
- 语气正式、友好、有号召力；科普稿提供必要技术解释，但不写成逐行接入教程。
- 不夸大“零开发量”，明确表述为：已有可调用 Agent 通常只需增加轻量适配层，无需重写内部模型、工具链或工作流。

## 短公告结构

1. 一段开场，明确邀请金融相关 Agent 队伍投递。
2. 用“Agent 之间的标准接口”解释 A2A。
3. 说明采用 A2A 是为了统一黑盒调用、公平评审和保留可复核证据，不要求公开内部实现。
4. 用三项最小接入内容降低顾虑：Agent Card、消息入口、标准结果返回。
5. 简列评审重点：接入稳定性、金融数据纪律、研究方法、回测与风险、解释与复现、提交完整度。
6. 列出最低投递材料：可访问的 Agent Card、可调用端点、鉴权说明、至少三个覆盖正常与异常边界的示例任务。
7. 以金融 Agent 方向举例并再次发出邀请。

## 招募型科普稿结构

1. 以“你的金融 Agent 已经能工作，距离参评可能只差一个标准接口”切入。
2. 解释 A2A 解决的发现、调用、任务状态和结果交付问题，并区分 A2A 与 Agent 内部实现。
3. 解释为什么统一采用 A2A：黑盒、公平、跨技术栈、可复核、不要求公开源码。
4. 用现有 Agent 到 A2A 的映射说明接入量：现有服务逻辑保持不变，在外层增加 Agent Card 和消息适配。
5. 说明需要稳定实现的最小闭环，以及流式、推送、多 Agent 编排等均不是所有作品的强制项。
6. 展开评审维度、一票否决项和示例任务要求。
7. 给出适合投递的金融 Agent 类型和准备清单。
8. 以明确行动号召结尾。

## 事实边界

- A2A 是面向独立、可保持内部不透明的 Agent 系统的开放互操作协议。
- Agent Card 用于声明身份、能力、Skills、服务接口与鉴权要求。
- 不承诺所有项目都能在固定时间内完成接入；开发量取决于现有服务是否已经具备稳定的请求入口和结果返回能力。
- 评分口径以仓库内 `docs/HACKATHON_FINANCE_RUBRIC.md` 为准。
