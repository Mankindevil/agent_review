# 睿评 A2A 黑盒 Agent 测评升级设计

**日期：** 2026-07-24  
**状态：** 已完成方案讨论，待书面审阅  
**适用对象：** 参赛者提交的完整投研 Agent，而非量化模型或单个 Skill

## 1. 背景与目标

现有睿评已经具备 Agent Card 校验、多模型点评、A2A 调用、Runtime 现场复刻和“夯 / 人上人 / NPC / 拉”评级，但正式评测仍存在四个问题：

1. 场景价值主要依赖关键词，容易被营销文案抬分。
2. 专业性评审没有完整绑定实际运行结果、证据和推导。
3. A2A 调用虽然返回原始响应，正式流水线却主要保留抽取后的文本，丢失 Task、Artifact、状态和上下文等黑盒证据。
4. 现场复刻结果承担了过多正式评分职能，但其“几分钟能否复刻”的反事实价值值得保留。

本设计将正式评测升级为：

> 只使用 Agent Card、参赛者提供的 Agent 使用示例，以及平台通过 A2A 接口直接观察到的行为；模型先评，人工随后复核；三维绝对分与现场复刻评级双轨输出。

目标包括：

- 覆盖量化、研报、风控、组合管理、事件研究、信息检索等不同投研 Agent。
- 每个评分子项由多个模型给出有证据的分数和理由。
- 人工评委在模型评测后查看证据和模型意见，再提交三维评分。
- 保留现场复刻，但将其定义为可替代性压力测试。
- 保留“夯 / 人上人 / NPC / 拉”的产品表达。
- 幽默点评有梗但不创造新事实。

## 2. 核心边界

### 2.1 参赛对象与复刻对象

三者必须严格区分：

```text
参赛者提交：完整 Agent
公开材料：Agent Card + Agent 使用示例
现场对手：根据公开材料临时复刻出的 Skill
```

参赛者不提交 Skill 使用示例，也不需要为 Card 中每个 Skill 单独提供示例。Card 中的 `skills` 只是 Agent 的公开能力声明和测试边界信息。

### 2.2 允许使用的信息

正式评测只允许使用：

- 参赛者提交的 Agent Card JSON；
- 参赛者提交的完整 Agent 使用示例；
- A2A Message、Task、TaskStatus、Artifact、Part、history、metadata 和扩展数据；
- A2A `Part` 直接携带或引用的产物；
- 平台直接测得的协议结果、响应时间、事件时间、成功率和稳定性；
- 由上述材料严格派生、且通过范围审查的隐藏测试。

评审模型不得自行浏览网页、查询外部数据库或补充未由 Agent 返回的事实。若 `Part.url` 表示 Agent 交付的产物，平台可在安全限制内读取该产物；不得沿链接继续任意浏览。

### 2.3 核心 A2A 无法证明的信息

以下信息不得伪装成已验证事实：

- 内部使用的模型、系统提示词或推理过程；
- 实际工具名称、参数、结果和调用链；
- MCP、浏览器、数据库或行情终端的内部调用；
- 记忆后端、读写日志、TTL 和隔离实现；
- 子 Agent 数量、角色、委派图和内部通信；
- 内部 Token、成本、缓存、规划和重试实现。

Card、metadata 或正文中的相关描述属于自报。只有可观察行为可以进入能力评分。

## 3. 投稿合同

一次正式投稿包含：

1. 一份可调用的 A2A Agent Card JSON；
2. 一个或多个完整 Agent 使用示例；
3. 可选的评测端点鉴权材料。鉴权材料仅用于连接，不进入评审上下文或评分。

Agent 使用示例支持单轮或多轮，使用统一结构：

```json
{
  "id": "example-1",
  "name": "组合风险复盘",
  "turns": [
    {
      "input": {
        "parts": [
          { "type": "text", "text": "分析本组合的行业集中度。" }
        ]
      },
      "expectedDeliverable": "行业暴露、集中度风险和调整建议",
      "acceptanceCriteria": [
        {
          "id": "risk-explained",
          "type": "model",
          "description": "指出主要集中风险并解释其影响"
        }
      ]
    }
  ],
  "constraints": ["不得把未知持仓补写成事实"]
}
```

规则如下：

- `id`、`name` 和至少一个 `turns[]` 为必填。
- 每个 turn 必须包含 `input.parts[]`；part 统一为 `text`、`data`、`raw` 或 `url`，并可带 `mediaType` 和 `filename`。
- 同一示例的 turns 默认复用一个 context；不同示例默认使用独立 context。
- `expectedDeliverable`、`acceptanceCriteria` 和 `constraints` 可选，只供测试编译、评审和现场复刻使用，不作为输入发送给提交 Agent。
- `acceptanceCriteria.type` 首版支持 `model`、`contains`、`exact`、`json-schema` 和 `numeric`；可执行类型必须提供相应 expected/schema/tolerance。
- 平台将 A2A 0.3 与 1.x Part 表示归一化到上述内部结构，再由选定 binding 序列化。

示例不包含 `skillId` 要求。平台使用整个 Agent Card 和全部 Agent 示例建立评测范围。

投稿进入正式评测时冻结声明与评测配置：

- Card 原文与哈希；
- 示例原文与哈希；
- 选定接口、协议版本和 Agent 版本；
- 评测规则版本；
- 隐藏测试包版本；
- 模型、Runtime 和预算配置版本。

远程 Agent 的内部实现无法通过 Card 真正冻结。平台额外记录评测窗口、端点、Agent version、可用的服务 build ID、每次响应指纹和首末运行时间；正式结果只代表该评测时间窗内观察到的版本。

参评资格只检查：Card 是否符合选定 A2A 版本、是否存在平台支持的接口，以及标准化预检能否完成至少一次合法 A2A 调用。Card 无效、没有受支持接口或端点在规定重试后仍不可调用，属于“参评资格失败”；进入正式测试后的超时和任务失败属于 Agent 表现，不与资格失败混淆。

Card 中声明但示例未展示、隐藏测试也无法合法覆盖的能力，显示为“声明但未验证”，既不加分也不扣分。

## 4. 证据模型

每条证据具有不可变 `evidenceId`，并分为四级：

| 等级 | 含义 | 例子 | 评分用途 |
|---|---|---|---|
| A | 平台直接测量 | HTTP 状态、总耗时、首事件时间、重复成功率 | 可直接进入客观能力分 |
| B | A2A 标准对象 | Task 状态、Artifact、contextId、Message Parts | 可证明本次黑盒行为 |
| C | 参赛者或 Agent 自报 | Card 描述、metadata 中的工具轨迹 | 用于声明和测试路由，不证明内部机制 |
| D | 评审模型推断 | “可能使用了搜索工具” | 只能解释，不得证明能力 |

正式能力分优先使用 A/B。C/D 只能降低或解释置信度，不能单独证明工具、记忆或多 Agent 协作。

每次运行保存：

- 请求与响应的原始 A2A 对象；
- 选定接口与协议版本；
- taskId、contextId、状态序列和时间戳；
- Message、Part、Artifact 和可返回历史；
- 平台开始、首响应、首事件和结束时间；
- HTTP、协议、解析、超时和取消结果；
- 测试、重复轮次、预算和配置版本；
- 原始证据哈希。

`Part.url` 作为 Agent 交付产物读取时，平台保存一次性内容快照、MIME、大小和哈希；评审只使用该快照，不跟随页面中的后续链接。

请求头、鉴权凭据和 Cookie 永不进入证据。原始证据采用受限访问和静态加密；进入模型、人工工作台或公开结果前执行密钥扫描和 PII 脱敏。公开证据保留哈希和必要上下文，但不公开原始敏感内容。

重试创建新运行记录，不覆盖原始记录。

## 5. 示例合同与隐藏测试

### 5.1 示例编译

示例编译器仅根据 Agent Card 与 Agent 使用示例提取：

- 用户目标；
- 输入和上下文；
- 明示约束；
- 预期产物类型；
- 可直接验证的验收点；
- 需要模型判断的专业要求；
- 不可验证的自报内容。

示例没有提供真值时，评审只能评价任务完成度、方法专业性、内部一致性、风险意识和产物可用性，不能声称验证了外部事实。

### 5.2 隐藏测试梯度

每个示例生成四级测试：

1. **原例复现：** 保留公开输入。
2. **等价改写：** 改变措辞、顺序或输出格式，不改变任务语义。
3. **参数与边界：** 在相同能力范围内改变参数、加入缺失值、冲突约束或异常输入。
4. **多轮上下文：** 使用同一 `contextId` 继续任务，测试澄清、纠错、更新和上下文隔离。

每类测试默认重复三次。独立测试使用全新上下文，多轮测试明确复用同一上下文。

### 5.3 防越界机制

隐藏测试采用“生成模型 + 独立范围审查模型”两阶段流程。范围审查必须确认：

- 未引入 Card 和示例之外的新领域；
- 未要求 Agent 展示未声明、未示范的能力；
- 未加入需要外部事实才能成立的隐藏答案；
- 难度提升来自表述、参数、边界或交互，而不是偷换任务；
- 提交 Agent 与复刻 Skill 接收完全相同的测试输入。

越界测试作废并保留审计记录，不影响选手成绩。

## 6. 三维评分合同

每个维度满分 100，三个维度等权形成三维绝对总分。

### 6.1 场景价值

| 子项 | 权重 |
|---|---:|
| Agent 必要性与任务复杂度 | 30 |
| 真实投研问题与决策价值 | 30 |
| 实用性与复用性 | 25 |
| 产品或协作形态新颖性 | 15 |

内部是否真的使用多 Agent 不可验证，因此新颖性只评价公开交互和可观察产品效果，不按自报的子 Agent 数量加分。

### 6.2 专业性

| 子项 | 权重 |
|---|---:|
| 任务完成度 | 25 |
| 专业方法与假设 | 25 |
| 证据与推导链 | 25 |
| 风险、局限与不确定性 | 15 |
| 产物结构与可用性 | 10 |

专业检查项根据示例动态生成，不固定要求回测、IC、因子或量化指标。

### 6.3 智能体能力

| 子项 | 权重 |
|---|---:|
| 原例和隐藏测试成功率 | 30 |
| 泛化、重复稳定性与鲁棒性 | 20 |
| 多轮上下文连续性 | 15 |
| A2A 合规与任务生命周期 | 15 |
| 响应效率 | 10 |
| 声明兑现与异常处理 | 10 |

工具、记忆和多 Agent 能力改为黑盒行为测试：

- 工具：有示例真值或可执行验收点时评价结果正确性；没有真值时只评价内部一致性、Agent 自带证据的完整性、数据时点表述和可复核性，不评价内部调用名称，也不声称核验了外部事实。
- 记忆：评价同一上下文保持、纠错后更新及不同上下文隔离。
- 多 Agent：评价复杂任务完成效果，不把内部协作声明当作事实。

### 6.4 人机权重

```text
场景价值 = 模型席 40% + 人工席 60%
专业性   = 模型席 40% + 人工席 60%
智能体能力 = 客观黑盒指标 50% + 模型席 20% + 人工席 30%
三维绝对总分 = 三个维度的等权平均
```

模型和人工都逐子项打分。对场景价值和专业性，先在每个子项内聚合评委分数，再按该维度的子项权重求和。智能体能力的模型分与人工分使用同样方式；客观黑盒分使用六个能力子项的客观指标：

| 客观子项 | 0–100 归一化规则 |
|---|---|
| 测试成功率 | 只对具有 required 可执行验收点的测试按锁定权重计算通过率；一次通过要求 A2A 正常终止且所有 required 可执行验收点通过。只有协议终态、没有可执行完成标准时，该测试的语义成功记为 `N/A`，终态只进入 A2A 合规 |
| 稳定性与鲁棒性 | 重复运行的终态成功一致性占 50%，可执行验收结果或输出 schema 一致性占 50% |
| 多轮上下文 | 锁定的保持、纠错更新和跨 context 隔离检查通过率 |
| A2A 合规 | Card、binding、响应对象、任务状态、Part/Artifact 及声明能力检查通过率 |
| 响应效率 | 每个测试预先锁定目标时长 `T` 与超时 `B`；不超过 `T` 得 100，`T` 至 `B` 线性降至 0，超时得 0。流式任务按首事件 30%、完成时间 70% 合成 |
| 声明兑现与异常处理 | Card 中适用的声明能力检查与标准化错误输入恢复检查的加权通过率 |

客观黑盒分按能力表的 30/20/15/15/10/10 权重合成。

适用性由示例编译器在执行前锁定，选手不能通过少报能力自行选择 `N/A`。A2A 合规和响应效率始终适用；稳定性在存在重复运行时适用；测试成功率按具备可执行完成标准的测试权重计算覆盖率；多轮上下文只在示例或合法隐藏变体需要状态时适用；可选声明只在 Card 声明后测试，但核心异常处理始终适用。`N/A` 只在客观黑盒分内部重分配权重，并在结果中显示原始覆盖率。客观覆盖率等于六个客观子项原始权重乘以各自可执行测试覆盖率之和。覆盖率低于 70% 时，智能体能力标记为“暂定”，最终评级不得为“夯”。

### 6.5 置信度

所有置信度使用 `0.00–1.00`。模型返回的 `confidence < 0.60` 视为低置信度。

每个适用评分子项的最终置信度按以下方式计算：

```text
E = 该子项各 rubric check 的最高证据等级均值
    A=1.00，B=0.80，C=0.35，D=0.10，无证据=0

Am = 1 - min(1, 模型分数四分位距 / 30)
Ah = 1 - min(1, 人工分数极差 / 30)
A  = 0.60 × Am + 0.40 × Ah
R  = 模型自报 confidence 的中位数

Csub = 0.50 × E + 0.30 × A + 0.20 × R
```

若尚未完成人工复核，临时置信度使用 `A = Am`，并明确标记为模型阶段结果。维度置信度是各适用子项 `Csub` 按该维度权重的加权平均；三维总分置信度为三个维度置信度的几何平均：

```text
Ctotal = (C场景 × C专业 × C能力)^(1/3)
```

结果页同时显示总置信度、各维度置信度和导致低置信度的证据缺口。C/D 证据会按上述等级权重自然降低置信度，但不会直接修改分数。

## 7. 多模型与人工评审

### 7.1 模型先评

每个子项由四个不同模型独立评分。每个模型必须返回：

- `score`
- `confidence`
- `evidenceIds`
- `findings`
- `counterEvidence`
- `uncertainties`
- `repairSuggestion`

模型之间互相不可见。每个子项先取模型分数中位数，再按维度权重合成模型席分数，不直接平均整张答卷。

出现下列任一情况时启用第五个模型：

- 同一子项最高分与最低分相差至少 20 分；
- 对是否完成任务、是否存在关键风险等结论发生冲突；
- 超过半数模型给出低置信度。

第五个模型使用同一证据独立评分，其分数加入该子项的五模型中位数，不替换或删除原评委分数。第五模型同样看不到其他评委意见。

评审模型调用失败属于平台错误，先以相同模型和配置重试；仍失败则启用预先登记的备用模型。四个首轮有效评审未齐时不得锁定模型席分数。

### 7.2 人工随后复核

人工评委不做盲审。模型评测完成后，人工可以看到：

- 原始 Card 与 Agent 使用示例；
- 测试类型和完整 A2A 证据；
- 四个模型的逐项分数、理由和分歧；
- 第五模型的仲裁意见（如有）；
- 客观黑盒指标。

每个作品默认由至少两名人工评委复核。每名人工评委对三个维度的全部适用子项分别打分，再由系统按已锁定权重合成三维分。人工推翻模型结论时必须引用证据。每个子项先取人工分数中位数；任一子项分差超过 15 分时增加一名仲裁评委，并以三名评委的中位数作为该子项人工分。

### 7.3 双轨隔离

三维绝对分必须在复刻竞技结果揭示前锁定：

1. 正式模型席只看提交 Agent 的 Card、示例和 A2A 证据；
2. 人工评委查看上述模型意见，但看不到复刻输出、竞技分或复刻优势；
3. 模型席和人工席锁定三维绝对分；
4. 竞技场再使用全新模型会话对匿名的 Agent 与复刻 Skill 输出评分；
5. 最后才计算复刻优势和夯拉评级。

“使用相同模型面板”只表示相同模型版本、量表和采样配置，不复用评审会话或上下文。这样复刻结果不会经由模型或人工意见间接进入三维绝对分。

### 7.4 幽默点评

幽默点评在模型与人工结构化评分全部锁定后单独生成。每个评分子项生成一条简短锐评，只能重写该子项已经锁定的 finding，不能添加新事实或影响分数。各模型原始的详细理由仍完整保留。

结果同时展示：

- 一句锐评；
- 严肃评分理由；
- 证据引用；
- 改进建议。

## 8. 现场复刻与双轨结果

### 8.1 定位

现场复刻衡量“公开信息下的快速可替代性”，不证明提交 Agent 的内部工具或架构。

三维绝对分与复刻对战分分离：

- 三维绝对分回答“这个 Agent 本身做得怎么样”；
- 复刻优势回答“它是否明显胜过几分钟拼出的临时 Skill”；
- “夯 / 人上人 / NPC / 拉”由两者共同决定。

复刻结果不重复计入三维绝对分。

### 8.2 复刻输入与隔离

Claude Code、Cursor、豆包等复刻 Runtime 获得：

- Agent Card 的语义字段；
- 全部公开 Agent 使用示例；
- 固定五分钟构建时间、Token 和本地工具预算。

复刻构建与执行默认禁止外部网络访问。若赛事未来提供统一基线工具集，必须通过 `rubricVersion` 明确列出，并对所有复刻 Runtime 使用同一版本。为防止复刻 Runtime 直接代理提交 Agent，`supportedInterfaces` URL、鉴权信息、文档 URL 和其他可用于调用或扩展原 Agent 信息来源的字段必须从复刻输入中移除。复刻 Runtime 不得看到：

- 提交 Agent 的运行输出；
- 模型评分和人工评分；
- 其他复刻 Runtime 的产物。

复刻构建阶段不得看到隐藏测试。执行阶段只能逐条接收与提交 Agent 相同的当前测试输入，不能预览完整隐藏测试包。

每个 Runtime 为整个参赛 Agent 构建一个临时 Skill，而不是为 Card 中每个 Skill 分别构建。

所有 Runtime 通过统一 `ReplicaAdapter` 交付：

```text
build(replicaPackage, buildBudget) → replicaArtifact
run(replicaArtifact, testInput, contextHandle, runBudget) → replicaResult
```

`replicaArtifact` 包含 Skill 指令、文件和 manifest，不得包含原 Agent 端点或凭据。`replicaResult` 统一包含：

- `status`
- `messageParts`
- `artifacts`
- `durationMs`
- `error`

复刻 Skill 不要求实现 A2A，但输出必须被归一化为与 A2A Part/Artifact 可共同评审的文本、数据或文件。构建和执行合同还必须锁定：

- 每个 Runtime 相同的五分钟构建时限、Token 上限和本地工具 allowlist；
- 每次测试与提交 Agent 相同的墙钟超时和输出大小上限；
- 各 Runtime 相同的执行 Token 上限；
- 独立测试使用全新临时工作区且无跨测试持久化；
- 多轮测试只在该示例内保留 `contextHandle`，示例结束立即清除；
- 复刻产物和输出进入与提交 Agent 相同的证据脱敏流程。

“有效复刻”要求 Runtime 基础设施健康、构建完成、产物通过安全与输出合同校验，并能启动标准调用。由临时 Skill 自身造成的单题崩溃、超时或无效输出计该题 0 分；Runtime 服务不可用、平台沙箱故障等基础设施问题使该复刻无效，不得算作提交 Agent 胜利。

### 8.3 同题竞技

提交 Agent 与所有复刻 Skill 执行相同的原例和隐藏测试。答案匿名并随机排序，由与正式专业性评审相同的多模型面板评价。

竞技分只比较双方共同可评的任务结果：

| 竞技子项 | 权重 |
|---|---:|
| 任务完成与约束满足 | 40 |
| 专业方法与结论质量 | 30 |
| 证据和风险意识 | 20 |
| 产物可用性 | 10 |

A2A 合规、Agent 延迟等提交 Agent 独有指标不进入竞技分，避免拿协议实现与普通 Skill 硬比较。

每个复刻 Runtime 重复运行三次，取其中位竞技分。最佳有效复刻基线是各 Runtime 中位数的最高值。提交 Agent 使用相同测试与重复次数计算竞技分中位数。

```text
复刻优势点估计 Δ = 提交 Agent 竞技分中位数 - 最佳有效复刻竞技分
```

平台在“测试 × 重复 × 模型评委”评分样本上执行固定 seed 的 bootstrap，计算 95% 置信区间。评级使用保守复刻优势 `Δc`，即该区间下界；区间跨越评级阈值时，结果页同时显示“差异未稳定”。

### 8.4 夯拉评级

初始评级阈值绑定 `rubricVersion`，后续可用真实评审数据校准。第一版规则为：

| 评级 | 条件 |
|---|---|
| 夯 | 三维总分 ≥ 80，场景价值 ≥ 60，客观能力覆盖率 ≥ 70%，且 Δc ≥ 5 |
| 人上人 | 三维总分 ≥ 70，场景价值 ≥ 50，且 Δc ≥ -2 |
| NPC | 三维总分 ≥ 55，场景价值 ≥ 36，且 Δc ≥ -10 |
| 拉 | 已通过参评资格但未命中以上条件，或场景价值 < 36 |

阈值按顺序命中第一条。参评资格失败不生成正式分数或夯拉评级，只显示“未通过参评资格”。平台故障或没有任何有效复刻基线时，只公布三维绝对分，评级标记为“待复刻”，不得把复刻故障当成提交 Agent 的胜利。

## 9. 系统架构

系统拆为七个边界清晰的模块：

1. **投稿与准入**
   - 接收 Card、Agent 示例和连接凭据；
   - 完成版本化 schema 校验、接口选择与快照冻结。

2. **示例编译器**
   - 生成示例合同、动态专业量表和候选隐藏测试；
   - 不访问外部事实。

3. **范围审查器**
   - 独立判断隐藏测试是否越界；
   - 只批准可从 Card 与示例推出的测试。

4. **A2A 黑盒执行器**
   - 执行单轮、Task、流式和多轮上下文测试；
   - 保存完整原始响应和平台计时。

5. **现场复刻竞技场**
   - 生成隔离的临时 Skill；
   - 以相同测试执行匿名同题竞技。

6. **模型评审席**
   - 执行四模型独立评分、第五模型分歧仲裁和幽默重写。

7. **人工评审与聚合**
   - 提供证据工作台；
   - 生成三维总分、复刻优势和最终评级。

数据流为：

```text
Card + Agent 使用示例
  → 准入与冻结
  → 示例合同
  → 隐藏测试生成与范围审查
  → 提交 Agent A2A 重复执行
  → 提交 Agent 不可变证据包
  → 四模型绝对分评审与分歧仲裁
  → 人工复核并锁定三维绝对分

Card 语义字段 + Agent 使用示例
  → 隔离的现场复刻 Skill 构建
  → 与提交 Agent 同题执行
  → 全新会话的匿名竞技评审

锁定的三维绝对分 + 复刻竞技结果
  → 三维绝对分 + 复刻优势 + 夯拉评级
```

复刻构建与运行可以和绝对分评审并行执行，但相关输出在绝对分锁定前必须保持密封。

## 10. 产品界面

### 10.1 参赛者提交与预检

提交页明确展示两个输入：

- A2A Agent Card；
- Agent 使用示例。

预检只验证协议、端点和示例可解析性，不生成成绩。页面不得出现“提交 Skill 示例”的文案。

### 10.2 人工评委工作台

- 左侧：Card、Agent 示例、测试类型和 A2A 证据时间线；
- 中间：模型逐项分数、理由、证据和分歧；
- 右侧：人工三维评分、证据引用和修改理由。

### 10.3 结果页

结果页依次展示：

1. 三维绝对总分和置信度；
2. “夯 / 人上人 / NPC / 拉”评级；
3. 提交 Agent 与各现场复刻 Skill 的竞技差值；
4. Card 声明与实际表现差距；
5. 原例、隐藏变体、多轮和稳定性成绩；
6. 各模型严肃意见和幽默锐评；
7. 人工最终意见和调整记录；
8. 不可验证项和证据置信度。

不同投研类型按赛道展示，不将不同任务的总分伪装成完全同质的横向能力排名。

## 11. 错误处理与复议

错误分为三类：

1. **平台错误**
   - 平台网络、存储、调度或评审模型故障；
   - 自动重试，不影响选手；
   - 达到重试上限后标记测试无效。

2. **复刻错误**
   - Runtime 构建或执行失败；
   - 不计为提交 Agent 胜利；
   - 其他有效复刻可继续，全部失败则评级“待复刻”。

3. **Agent 错误**
   - Agent 超时、协议错误、无效响应或任务失败；
   - 计入成功率和智能体能力。

失败归因采用固定探针：

1. 检查调度器、证据存储和组织方控制端点；
2. 从独立 worker 对同一 Agent 端点执行一次受限连接复核；
3. 若控制探针失败或多个无关 Agent 同时失败，归为平台错误；
4. 若控制探针正常且只有目标 Agent 持续失败，归为 Agent 错误；
5. 无法确定时标记“归因待审”，该次运行暂不计分并交由运营人工裁定。

资格预检最多执行一次初始请求和两次退避重试。正式测试的三次重复是预先计划的统计样本，不是失败后挑选结果；平台错误可在相同 seed、配置和输入下补做一次替代运行，Agent 错误不得用额外重试覆盖。

复议必须针对具体测试、证据或评分。原始运行永久保留；复议运行创建新版本。只有平台故障允许同配置重跑，禁止通过无限重跑挑最高分。

## 12. 与现有系统的关系

现有能力可以保留：

- Agent Card 上传、URL 发现和安全请求；
- A2A 1.0 与 0.3 兼容调用；
- SSE 阶段进度；
- 四模型评审卡；
- Claude Code、Cursor、豆包 Runtime；
- 重试历史和“夯拉”展示。

需要替换或扩展：

- `src/a2a.js`：从最低限度校验升级为版本化完整校验，并规范化保存原始 A2A 证据；
- `src/pipeline.js`：不再只消费 `.text`，改为编排测试、复刻、证据、模型和人工阶段；
- `src/scoring.js`：用版本化三维评分、竞技分和双轨评级替换关键词与长度启发式；
- `src/prompts.js`：采用证据 ID、置信度、反证和不确定性输出合同；
- 前端：新增证据回放、人工工作台、复刻优势和声明—实测差距。

## 13. 验收标准

设计落地后必须满足：

1. 参赛输入只有完整 Agent Card、Agent 使用示例和必要连接凭据。
2. 页面和数据模型不把参赛 Agent 示例称为 Skill 示例。
3. Agent 示例使用明确的 turn/part schema，并支持 A2A 0.3 与 1.x 归一化。
4. Card 自报能力不会直接增加正式能力分。
5. 正式评测保存完整 A2A 原始对象，不只保存抽取文本。
6. 结果声明明确的评测时间窗，不声称冻结了远程 Agent 内部实现。
7. 原始敏感证据受限保存，模型、人工和公开版本均经过密钥与 PII 脱敏。
8. 隐藏测试只能从 Card 和 Agent 示例派生，并经过独立范围审查。
9. 原例、等价、边界和多轮测试均支持重复运行。
10. 无可执行完成标准时，协议正常终止不会被冒充为客观任务成功。
11. 客观能力分可按唯一公式计算，并公开适用项及覆盖率。
12. 分项、维度和总分置信度可按唯一公式计算。
13. 四个模型对每个子项独立评分，高分歧触发第五模型。
14. 人工在模型完成后逐子项复核并提交三维分。
15. 三维绝对分在任何模型或人工看到复刻结果前锁定。
16. 幽默点评在分数锁定后生成，且不增加新事实。
17. 现场复刻 Skill 不能调用原 Agent；构建阶段不能看到隐藏测试包或原 Agent 输出，执行阶段只能逐条接收当前测试输入。
18. 三维绝对分不重复包含复刻差值。
19. “夯 / 人上人 / NPC / 拉”同时受绝对分、客观覆盖率和保守复刻优势约束。
20. 平台、复刻和 Agent 错误使用不同计分语义。
21. 重试和复议不会覆盖原始证据，也不能用于挑最高分。

## 14. 实施分期

本设计覆盖完整产品方向，实施计划应拆为四个可独立验收的阶段：

1. **证据与评分底座**
   - 完整 A2A 证据、版本化数据模型、三维评分合同。

2. **动态测试与模型评审**
   - 示例编译、隐藏测试、范围审查、四模型与分歧仲裁。

3. **现场复刻双轨评级**
   - 隔离复刻输入、同题竞技、复刻优势和新评级。

4. **人工工作台与治理**
   - 人工复核、证据回放、复议和结果页。

每一阶段应保持现有可运行流程可回退，并通过功能开关逐步启用。
