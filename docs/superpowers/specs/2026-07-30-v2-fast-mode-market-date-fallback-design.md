# V2 快速评测与 Agent 交易日回退设计

## 目标

1. 将本机 V2 评测切换到快速档，减少隐藏测试与 Replica 的重复执行。
2. 当分析请求未显式指定日期时，让市场 Agent 使用最近一个已完成交易日，避免盘中、周末或节假日因为当天数据尚未完成而失败。
3. 在产物中明确披露日期回退，不静默改变数据口径。

## V2 快速档

根目录 `.env` 增加：

```dotenv
A2A_MULTI_TURN_ENABLED=false
A2A_REPEAT_COUNT=1
```

该配置跳过生成的隐藏 multi-turn 变体，并把 Phase 1、Phase 2 与 Replica 的每格重复次数降为 1。提交材料本身包含的多轮示例仍按原样执行。以 5 个单轮示例计算，测试格数量由约 63 降至约 16。

配置只影响新创建的评测。已经锁定测试计划或正在运行的评测继续使用创建时的配置，避免中途改变评分口径。

## 日期选择语义

### 显式日期

请求包含 `YYYY-MM-DD` 或结构化 `date` 时保持严格语义：

- 不自动回退。
- 未来日期、未收盘当日或非交易日继续返回明确错误。
- 这样可避免调用者请求某日数据却收到另一日结果。

### 隐式日期

请求未包含日期时：

1. 以 `Asia/Shanghai` 计算当前自然日。
2. 向 Panda Data 查询最近已完成交易日。
3. 若当前自然日尚未收盘、休市或没有完整数据，使用最近已完成交易日作为实际报告日。
4. 若当前自然日已经收盘且 Panda 确认其为最新已完成交易日，则使用当天。
5. 若无法取得最近已完成交易日，任务失败并保留 Panda 错误，不猜测日期。

不采用简单的“自然日减一”，因为周末和节假日仍可能没有数据。

## 数据流与职责

- `task-service` 只负责解析操作；是否存在 `operation.date` 即为显式/隐式日期边界。
- `orchestrator` 在获取按日期划分的运行锁之前，通过现有 Panda bridge 查询 `get_last_trade_date`、必要时查询 `get_prev_trade_date`，并以 `get_trade_list` 验证候选日期确有市场数据。
- Panda Worker 使用解析后的实际报告日执行完整采集，并再次执行现有交易日历与完整性校验。
- Evidence Pack、Run Trace 和报告渲染器使用实际报告日，并记录日期选择元数据。

建议的元数据：

```json
{
  "dateSelection": {
    "requestedDate": "2026-07-30",
    "effectiveDate": "2026-07-29",
    "mode": "latest-completed-trading-day",
    "reason": "REQUEST_DATE_NOT_COMPLETED"
  }
}
```

若未发生回退，`requestedDate` 与 `effectiveDate` 相同，`reason` 为 `null`。该字段不包含凭据或 Panda 原始响应。

## 用户可见说明

发生回退时，Markdown、HTML 和纯文本报告的运行概览中显示：

> 请求日期 2026-07-30 尚未形成完整收盘数据，已使用最近已完成交易日 2026-07-29。

Agent 的终态保持成功或数据降级状态，而不是因为正常的盘中回退进入失败状态。

## 并发边界

本次不改变同一报告日的运行锁。若 V1 与 V2 同时请求同一个已完成交易日，仍由现有锁阻止重复写入。排队或复用正在运行任务属于独立改造，避免与日期回退混合实施。

## 错误处理

- Panda 登录、网络或 SDK 错误：任务失败，不使用推测日期。
- 最近交易日为空或格式非法：任务失败并记录数据源错误。
- 显式指定未完成日期：任务失败，不回退。
- 隐式日期成功回退：任务继续，报告和证据中记录回退。

## 验证

新增或更新测试覆盖：

1. V2 配置读取到 `multiTurnEnabled=false`、`repeatCount=1`。
2. 隐式请求在上海盘中选择 Panda 返回的最近已完成交易日。
3. 周末或节假日隐式请求选择最近交易日，而不是自然日减一。
4. 上海收盘后且当天已完成时使用当天。
5. 显式指定未完成日期仍失败。
6. Panda 无法给出最近交易日时不静默回退。
7. Evidence Pack、Run Trace 与三种报告格式包含一致的日期回退说明。
8. 现有 Agent、Worker、报告验证和 V2 执行调优测试全部通过。
