STAGE 00 / GATE

A2A 协议准入

这一阶段只决定“能不能进入考场”，不产生分数。

必须满足

  • Agent Card 是 JSON 对象；
  • 存在非空 name 与 description；
  • 至少声明一个 skill；
  • 每个 skill 都有 id / name / description；
  • 存在 A2A 1.0 supportedInterfaces，或兼容 0.3 的顶层 url。

失败如何处理

HTTP 400

任一必填项缺失，创建评测直接失败，不会用 0 分假装跑完。Card URL / 服务发现还会检查 HTTP(S)、私网地址限制、1 MB 响应上限与禁止重定向。

支持 HTTP+JSON、A2A 1.0 JSON-RPC SendMessage 和 0.3 message/send。
STAGE 01 / RULE ENGINE

投研 Agent 必要性：五维等权

判断任务是否真的需要数据、时点、回测、风险与多步研究链路，而不是一次行情问答。满分 100，五个维度各占 20%。

CComplex signal groups命中的复杂信号组数，取值 0–8
SSimple-transform signal是否命中简单变换组，取值 0 或 1
KSkill count (K)Card 中声明的 skill 数；取 skill 中的 K，避免与 S 冲突
NNumber of use cases测试用例数量，正常范围 1–5
UUse-case indicator有测试用例为 1，否则为 0；正常提交恒为 1
BCapability bonusstreaming +5、pushNotifications +6、extensions +4

变量作用域：本节的 C 只表示 Complex signals。最终分档章节会重新定义局部变量，其中 C 表示 Claude Code 均分；两套公式不会混用。

BOUND FUNCTION / 截断函数

clamp(x) = min(100, max(0, x))

x < 0→00 ≤ x ≤ 100→xx > 100→100

这里的 clamp 只接收一个参数时，默认下限是 0、上限是 100。例如 clamp(-7)=0，clamp(63)=63，clamp(118)=100。

MATCH PIPELINE / 命中流程
  1. 拼接 Card 描述、每个 skill 的名称/描述/tags/examples，以及全部测试 prompt；
  2. 8 个复杂信号正则分别扫描一次完整文本，不区分中英文大小写；
  3. 某组匹配至少一次，该组记 1；同组重复出现不累计；
  4. 同一段文字可以同时命中不同组，例如“历史成分股月频因子回测”会命中时点、因子与回测组。

STAGE 02 / MODEL PANEL

金融专业度：多模型独立审稿

评审只看公开 Agent Card；没有声明的数据口径、时点与风险控制一律按缺失处理，不脑补实现。

维度主要看什么常见失分项
研究严谨性问题定义、假设、统计方法、基准与稳健性只谈收益，不说明假设和对照组
数据纪律来源、口径、截止时点、历史成分与授权边界未来函数、幸存者偏差、复权含糊
回测可信度成交时点、成本、滑点、可交易性和样本外验证信号即成交、零成本、忽略停牌涨跌停
风险合规回撤、暴露、压力测试、局限和非投资建议承诺收益、荐股或绕过授权数据
可复现性参数、版本、样本期、随机种子与输出契约只有结论，无法重复实验

单模型返回

{
  "score": 0-100,
  "dimensions": { "五个维度": 0-100 },
  "comment": "简评",
  "risk": "首要风险"

当前后端使用模型返回的 score 作为该评审总分，不会再从五个维度二次求平均。

汇总公式

有效评审分之和 ÷ 有效评审数
  • 成功且 score > 0 才进入平均；
  • 调用失败保留错误并显示 0，但不进入平均；
  • 全部失败时专业度为 0；
  • 专业度目前用于报告与审计，不直接决定最终四档评级。
DEMO 模式使用输入 Card、评审 ID 和 seed 生成确定性模拟分；它用于走通产品流程，不代表真实模型意见。
STAGE 03 / RECONSTRUCTION

Runtime 现场直出：只凭 description 生成 Skill

Claude Code、Cursor Agent、Doubao Agent 只拿到 Agent Card 顶层 description 的相同原文，不拿完整 Card、原 Agent 实现或历史输出。

1截取 description唯一任务信息
2生成 Skillname / description / instructions / tools
3结构校验无效 JSON 自动纠错重试一次
4进入对打用原始用户 prompt 执行

信息防火墙

复刻端看不到 name、skills、examples、tags、capabilities、接口地址和提交 Agent 输出。它不能在 Agent 上继续增强，只能把 description 临时解释成 Skill。

构建失败

该 Runtime 仍保留在对战表中，但每个测试用例都会生成失败条目，实战分强制为 0。其他 Runtime 与提交 Agent 继续执行。

为什么只给 description这条基线回答的是“强模型只看产品描述，现场直出 Skill 是否已经足够”。若把完整 Agent Card、skills 或原 Agent 输出交给 Runtime 再增强，比较对象就被污染，无法证明固定 Agent 流程带来了独立价值。
STAGE 04 / ARENA

同题研究压测：只看可见最终输出

每个用例分别运行提交 Agent 与三个复刻 Skill。评分器不读取隐藏思维链，也不因为收益数字更夸张而加分。

任务完成38–80

输出大于 80 字为 80；26–80 字为 66；否则 38。

数据证据20–96

先检查来源与口径；存在参考快照时，再校验必填数据事实、数值容差与冲突。

方法严谨50 / 86

是否报告 IC、基准、收益风险、换手、成本、暴露或置信区间。

风险披露44 / 88

是否声明假设、局限、回撤、压力测试与不构成投资建议。

单局实战分round(clamp(四维均值 + seed 稳定扰动))稳定扰动范围 −4 到 +4；执行失败时无论公式结果多少都覆盖为 0。

多用例汇总

每个选手的实战均分 = 该选手所有测试用例分数的算术平均，保留 1 位小数。

“同 Prompt”的含义

提交 Agent 收到原始 prompt；Runtime 执行提示会带上刚生成的 Skill，但其中的用户原始 prompt 不改写。当前评分不使用用例中额外的结构化验收点。

数据接入边界PandaAI 参考快照可验证声明的行情与财务锚点；复杂回测收益仍需结构化回测配置、逐期净值复算、结果哈希与人工抽检。
STAGE 05 / FINAL VERDICT

最终分档：按顺序命中第一条

设 A 为提交 Agent 实战均分，C 为 Claude Code 均分，D 为豆包均分，N 为必要性分。

1拉N < 36

任务不值得 Agent 化。即使实战分高，也先判“拉”。

2夯A − C ≥ 3

提交 Agent 明显压过 Claude Code 复刻基线。

3人上人0 ≤ A − C < 3

不低于 Claude Code，但领先不足 3 分。

4拉A − D < 0

低于 Claude，同时连豆包基线也没守住。

5NPC其他情况

低于 Claude，但不低于豆包。

顺序很重要：必要性不足拥有最高优先级；“低于豆包”的判断发生在“不低于 Claude”的判断之后。专业度均分当前不会改变这棵分档决策树。

STAGE 06 / REVIEW CONTROL

单步重试与综合重算

重试不是多跑几次挑最高分，而是用最新结果替换旧结果。

重跑模型

只替换指定 reviewer 的专业度结果，再计算有效评审平均。

重建 Runtime

替换 Skill，并重新执行所有同 Prompt 对测用例，避免构建物与输出版本错位。

重跑一局

只替换某个用例中的某位选手结果。

重试完成后专业度 → 各选手均分 → 差值 → 最终分档，全部重算前后摘要、耗时与目标 key 写入 retryHistory；最多保留最近 100 条。
固定 Seed

根 seed 会为每个 reviewer、Runtime、用例和 Judge 派生稳定子 seed；单步重试沿用相同子 seed。OpenAI-compatible 与方舟链路会发送 seed，Cursor CLI 和外部 A2A Agent 只能尽力复现。

STAGE 07 / DISCLOSURE

你应该如何解读结果

报告同时标注 LIVE、DEMO、RULES、FAILED 或 MIXED，避免把模拟产物误认为真实调用。

能说明

同一套公开规则下的相对表现、Agent Card 的工程完整度、可见输出质量、各适配器是否成功。

不能说明

行情锚点验真不等于完整回测复算，仍不能单独证明因子有效性或未来收益，更不能作为投资建议。

数据接入后

已支持 PandaAI 快照、事实容差和结果指纹；后续继续增加历史成分校验、成本敏感性、样本外测试和逐期净值复算。
